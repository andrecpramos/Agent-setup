# DESIGN.md library

`assets/brands/<folder>/DESIGN.md` holds one extracted design system per brand,
in the Google Stitch DESIGN.md format: YAML tokens (colors, typography, spacing,
radii) followed by prose sections (atmosphere, color roles, typography,
components, layout, elevation, do's and don'ts, responsive rules, agent prompt
guide). The catalogue, grouped by category with a one-line look per brand, is
[INDEX.md](INDEX.md).

Everything under `assets/brands/` and `INDEX.md` is vendored from
[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md)
(MIT, see [the licence](../../licenses/awesome-design-md.txt)) and regenerated by
`agent-setup vendor sync`. Do not edit those files. Adapt a copy into the
project instead.

Read `.claude/overlays/design-md-library.md` first if it exists: this project's
adaptation (brands it has ruled out, the licensed fonts it owns). It wins where
the two disagree.

## If the project already has a DESIGN.md

That file is the source of truth and it wins. Use this library only when the user
asks to change the visual direction. That is a redesign: follow
[design-taste-frontend](../design-taste-frontend/SKILL.md) Section 11 (redesign
protocol), which decides between preserving and overhauling.

## Procedure

**1. Pick one reference.**
- The user named a product ("like Linear", "Stripe-style") → that brand's file.
- The user described a look ("dark, technical, one emerald accent") → shortlist
  two or three rows from [INDEX.md](INDEX.md), read the `description:` line at
  the top of each candidate's DESIGN.md, pick the closest.
- Two candidates fit equally and lead to visibly different sites → ask the user
  once, showing both one-line looks. Otherwise decide and say which one you chose.

**2. Read the chosen DESIGN.md completely.** The token block alone misses the
rules that make the look work: what the accent is *never* used for, how surfaces
stack, what the do's and don'ts forbid.

**3. Adapt it into the project's own `DESIGN.md` at the repo root.** Do not
clone the brand.

| Keep from the reference | Replace |
|---|---|
| Surface and elevation system, spacing scale, radius system | Brand accent → the client's brand color, unless the user explicitly wants the reference palette (personal or demo work) |
| Type scale, weights, tracking, line-heights | Proprietary typefaces → licensed substitutes (table below) |
| Component states, motion feel, density | Title, product names, example copy → the project's |
| Do's and don'ts, responsive rules | |

Then:
- Put a provenance line under the title: `Derived from the <Brand> DESIGN.md
  (awesome-design-md), adapted for <project>.`
- Add a `Configuration` section with the design-taste-frontend dials that match
  the reference (`DESIGN_VARIANCE`, `MOTION_INTENSITY`, `VISUAL_DENSITY`, each
  1-10) so the build step starts from them instead of the generic baseline.
- Mixing is allowed in one form only: one base system plus one borrowed aspect
  from a second (for example Linear surfaces with Stripe's gradient treatment).
  Record the borrowing in the provenance line. Blending three or more produces
  no recognisable system at all.

**4. Hand off to the build.** Continue with
[frontend-design-workflow](../frontend-design-workflow/SKILL.md) step 2. From
here on the project DESIGN.md outranks design-taste-frontend's default font and
palette bans. A font a brand chose deliberately is not an "AI default".

## Hard limits

- **Never reproduce logos, wordmarks, mascots, product names or brand
  illustrations**, and never build a page that could pass for the real brand's
  site. A pixel-faithful clone of a payments or crypto brand is the shape of a
  phishing page, whatever the intent. The library provides a design *language*,
  not an identity.
- **Never ship a proprietary typeface** the project has not licensed. Most brand
  fonts here are custom or commercial.

## Typeface substitutes

Open-licensed fonts that already appear in the library can be used as-is:
**Inter, Geist, Geist Mono, IBM Plex, DM Sans, Rubik.**

For proprietary faces, substitute by feel. These fonts are free for web use.
None is metric-compatible, so re-check tracking and line-height after swapping.

| Reference feel | Examples in the library | Substitutes |
|---|---|---|
| Neo-grotesk / Swiss | Söhne, SF Pro, Unica77, ABC Diatype, Universal Sans, Saans, Super Sans | Geist, Inter Tight, Hanken Grotesk, Schibsted Grotesk |
| Geometric / friendly | Circular, Airbnb Cereal, Euclid Circular, Coinbase Sans, Basier Square, Styrene, Roobert | Plus Jakarta Sans, Figtree, Manrope, Outfit, Satoshi |
| Wide / technical display | BMW Type Next, NVIDIA, NouvelR, FerrariSans, PlayStation SST | Archivo (expanded widths), Space Grotesk; Unbounded for display only |
| Monospace | Brand monos, SF Mono | Geist Mono, JetBrains Mono, IBM Plex Mono |

**About Inter.** Many brand files use Inter for body and UI text, and
design-taste-frontend flags Inter as an AI default. Both are right. Inter
*because the reference specifies it* is a deliberate choice: keep it for body
and UI text. Give headings character from the reference's display face, or its
substitute above, so the page does not read as "Inter + slate-900".
